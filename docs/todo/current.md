## 測るときの作法（本日3回ひっくり返った）

**最初の測り方のままなら、3件とも間違った結論を出していた。**

1. **N 回 green は陰性対照とセットで。** #156 の「修正後4回 green」は、**未修正でも4回 green** だったので判別力ゼロだった。
   主張は「直った」ではなく**余裕の量**（2.0〜2.5倍 → 12〜15倍）で書く。→ 条文化 = **#206**
2. **「まだ落ちていない」を根拠にしない。** #156 の CI 上の余裕は実測すると **1.96倍**＝ローカルで 50% 落ちたのと同水準だった。
   緑の記録は**余裕がどれだけ残っているかを何も語らない**。
3. **射程は「どこにあるか」でなく「何であるか」で数える。** 生成物コミット型はパス判定で 11艦・**内容（バンドラの指紋）で 1艦**。
   パス判定のまま配っていたら、**永久に緑で何も検査しないゲート**を10艦へ配っていた（＝G-6 に自分で違反）。
4. **不在の主張には陽性対照を1本。** 「0件」は検出器が死んでいても出る。
5. **条文化のときは、issue で発見し、正本で確定する。** issue は正本のスナップショットであって正本ではない。
   **「正本」には起草側の実装とそのコメントも含む**（本日、正本にしかない追記を1件回収／起草側の原文が現行実装と食い違っていた）。
6. **本文を持つ CLI 呼び出しは本文をファイル経由で。** `gh … --body "…"` はシェルが本文を展開し、
   **壊れても呼び出しは成功する**（本日実踏・#215）。relay の README が定めているのと同じ理由。
