1. 🔑 **列挙で書いた検査は、列挙に無いものを緑にする。** 08-23 だけで**4件**（lock ゲート / スロット既定の名前空間 / 部品の到達プレフィクス / baseline の floor）。⇒ **#353 では列挙をやめ、パレットをテーマから読む形にした。**
2. 🔑 **平均誤差だけを見る検査は「意図して引かれた区別の削除」を誤差として通す。** ⇒ **実在する2つの値が同じ段へ潰れないか**を判定に足す（vault 提案）。radius と色の両方で使っている。
3. 🔑 **テストは「本体」ではなく「本体の代理」を検査していることがある。** 代理と本体が同じ部品に居るあいだは等価だが、**本体が上流へ移った瞬間に別物になり、代理は緑のまま残る。** ⇒ **実装を上流へ移す作業は、この形の回帰を構造的に作る。**
4. 🔑 **道具の窓が主張の射程より狭いと、静かに過小に出る。** `grep -A3` は範囲を跨げない・1行 grep は複数行 JSX を跨げない・トークン定義だけ数えると直書きが落ちる。**「無い」「0件」を言う前に、別の表現形式を1つ探す。**
5. 🔑 **測れなかったものは「測れなかった」と書く。** 08-23 は数字を出さない判断を**2回**した（Button の display 分布・`className` を受け取らない部品数）。
6. ⚠️ **PR が2本並んでいるとき、それぞれの緑は「相手が入る前の緑」。** 片方が検査を足し、もう片方がその検査の対象を変えるなら、**`BEHIND` のままマージすると組み合わせを誰も走らせない。**
