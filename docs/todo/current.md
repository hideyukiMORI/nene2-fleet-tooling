## 測るときの作法

**過去のセッションで実際にひっくり返ったものだけを置く。** 新しく踏んだら足す。

1. **N 回 green は陰性対照とセットで。** #156 の「修正後4回 green」は**未修正でも4回 green** だった＝判別力ゼロ。
   主張は「直った」ではなく**余裕の量**で書く。→ 条文化 = **#206**
2. **「まだ落ちていない」を根拠にしない。** 緑の記録は**余裕がどれだけ残っているかを何も語らない**。
3. **射程は「どこにあるか」でなく「何であるか」で数える。** パス判定のまま配ると
   **永久に緑で何も検査しないゲート**を配ることになる（＝ G-6 に自分で違反）。
4. **不在の主張には陽性対照を1本。** 「0件」は検出器が死んでいても出る。
5. **条文化のときは、issue で発見し、正本で確定する。** issue は正本のスナップショットであって正本ではない。
6. **本文を持つ CLI 呼び出しは本文をファイル経由で。** `gh … --body "…"` はシェルが本文を展開し、
   **壊れても呼び出しは成功する**（#215・relay の README と同じ理由）。
7. 🆕 **道具の単位を、測りたいものの単位に合わせる。** 08-05 実踏: 艦隊の allowlist を素の
   `grep 'GHSA-…'` で数えたら **14艦すべてが該当**と出た。jsonc の**コメント中の「なぜ外したか」まで拾う**ため。
   **撤去済みの艦ほど誤検出される。** 配列だけを見て測り直すと **5艦**。→ #226 / #243
8. 🆕 **空き番の判定は台帳では足りない。** 未確定の予約は台帳に載らない（上記 🔴 EX-8）。
9. 🆕 **自分が配る数字にも「いつの実測か」がある。** 同じ計測を18時間差で取ると
   allowlist **23件/8艦 → 20件/5艦**（#229 の波が着地したため）。**基準線の数字をそのまま配ると
   既に片付いた艦を叩く**。→ #237 / #245（`_work/fleet-muster.md` M-2 に条文化）
