32. 🆕 **測っていないものを「0」と書かない。** Dependabot の 403 は「無効」であって「脆弱性なし」ではない（**22リポ**）。
33. 🆕 **出所の違う数字を同じ表に並べない。** 「sakura-FT 3件」は Dependabot ではなく `composer audit` 由来の疑い。
34. 🆕 **数え方を先に決めてから数える。** 同じ母集団が **98（延べ）/ 66（直す箇所）/ 35（判断）** になる。
    **マニフェストが複数ある艦は延べが倍化する**（records-site = 22×2）。
35. 🆕 **手元と CI は別の検出器であり、どちらが厳しいかはルールごとに違う。** → #282
    「新しい版なら安全」も「CI の固定版のほうが甘い」も、**両方とも外れる**。
36. 🆕 **検査は痕跡を残す形で置く。** ログに `run:` 行が残らない検査は、**存在しない検査と区別できない**。 → #281
37. 🆕 **待つと決めた玉は、待つ先の期日に置く。** 行の末尾に「今日はやらない」と書いても、**期限だけが取り残されると
    毎日 🔴 で出る**（hub が 08-19 に `NENE2` の行で実際に踏んだ）。⇒ **板が「本当に遅れているもの」と
    「待つと決めたもの」を区別できなくなる。** 待ち先が別の玉なら、**その玉と同じ期日に揃える**（＝同じ束だと示す）。
    🔴 **適用条件**: **期日を置けない待ちが存在する。** 待ち先が**他人の release**（例: `vitepress` が vite 6+ を引く版を出すこと）なら、
    こちらから期日を決められない。⇒ **それは「待ち」に分類してはいけない。放置になる。**
    **期限つき例外（ID／理由／期限／解除条件）で受けるか、玉ごと別の解に振り替える。**
38. 🆕 **射程と可達性は別の軸。**「1回の判断で N リポ片づく」は、**その判断が実行可能であることを含意しない**。
    08-19 に自分でこれを踏んだ: `vite` / `esbuild` を「9リポ・5リポに効くから先に」と推したが、
    **4リポとも `fixAvailable=False`**（`vitepress` 1.x が `vite ^5` に固定・vitepress に 2.x は無い）＝**閉じられない玉**だった。
    ⇒ **射程だけで順序を決めると、いちばん広い玉がいちばん動かない玉だったということが起きる。**
    🔑 **「修正版がある」と「このリポで上げられる」は別の主張。** advisory 台帳（`first_patched_version`）の値を、
    **リポの可達性の主張に使わない。**

39. 🆕 **正しい状態を書くことが、現時点では嘘を書くことになる場合がある。** → **docs を code より先に進めない。**
    08-20 の実例: serve の「`100000` = ¥1,000」は **×100 の例だが、serve のコードが ×100 なので現状の正確な説明**だった。
    正典どおりに直すと**チュートリアルどおりに入力した人が桁違いの予算を作る**。
    🔑 **「誤った例がある」だけでは直すべきか決まらない。決めるのは「その艦のコードがどちらか」。**
    ⇒ コードが正しい艦は**例を直す**／コードが違反している艦は**例に触れず逸脱の印を置く**。**数値とコードは是正波で同時に。**
40. 🆕 **規約は「艦隊の標準」を書く場所、コメントは「このコードの説明」を書く場所。層を混ぜない。**
    規約文に正典を書くのはコードが違反していても矛盾しない（違反は別レイヤーの既知事項）。
    **コードのコメントに正典だけを書くと、そのコードが違反している場合に嘘になる。**
    ⇒ コメントには **「正典 ＋ 現状はそれに違反 ＋ この文言をコピーするな」の3点セット**を置く。
41. 🆕 **逸脱はコピーで伝播するが、対策はコピーされない。**
    serve の `format-money.ts` は deal と**冒頭6行が完全一致**で生まれた。clear の `model.ts` は
    「`*_cents` are integer cents (yen × 100), **like everywhere else**」と**逸脱を標準として固定**していた。
    ⇒ **打つべきは「これをコピーするな」であって「正典はこうだ」ではない。**
    ⇒ 同型: relay は事故2件を経て「本文はファイル経由」に到達したのに、**`board.sh add` は同じ地雷を持ったまま残っていた**。
42. 🆕 **定義があることは、読まれたことを意味しない。** 08-20 の実測で、**正しい定義を持っていた艦は6艦中5艦**。
    `clear` は自艦の glossary で **「1/100円として読むのは誤用」と名指ししながらコードがその誤用をしていた**。
    ⇒ **決定要因は定義の有無ではなく「実装者が定義を読んだか、コードをコピーしたか」。**
43. 🆕 **`git add -A` は「自分が触ったもの」ではなく「そこにあるもの」を拾う。**
    08-20 に vault で無関係な `.mcp.json` を PR へ巻き込んだ。⇒ **コミット対象はファイル名で明示する。**
    🔑 **`git status` を「自分の作業の一覧」だと思わない** — 置いたのは自分ではなかった
    （hub の `seed-all.py` が同じ夜に書き込んでいた）。**他人の道具が同じ木に書き込むことがある。**
44. 🆕 **ブランチを切る前に、切り元が `origin/main` と一致しているか見る。**
    08-20 に profile で前の作業ブランチから切ってしまい、**差分に射程外の 6242行**が出た。
    🔑 **「差分に射程外のファイルが出る」は、古いブランチが何かを静かに巻き戻す入口。**
    ⇒ マージ前に **`git diff origin/main origin/<branch>`（実際にマージされる内容）と逆向き差分**の両方を見る。

45. 🆕 **装置を入れる前に、その装置が何を言うかを先に聞く。** 08-22 に corpus で `npm run audit` を
    **配線する前に実走**したら high が1件出た。そのまま足せば「ゲートを入れた瞬間に赤」＝順序事故。
    🔑 **allowlist で逃がすのは「入れた」ではなく「逃げ道を1つ作った」。**（逃げ道ゼロは 0件/分母15）
46. 🆕 **参照実装からは「意図」を写す。「文字列」を写すと inert になる。**
    serve の `failure() && (schedule || simulate)` を schedule の無い艦へ写すと、
    **装置はあるのに原理的に赤にならない**ものが増える。
    ⇒ **通知する event ＝ その workflow が「無人で走る」event を列挙する**（hub 裁定・vault 発）。
    `schedule` は常に無人／`push`（マージ後）は**マージした人が立ち去れば無人**／`pull_request` は**含めない**。
    🔴 **自艦の #287 がこれを踏んでいた**（`on.push.branches: [main]` を持つのに push を条件に入れていない）。
    **指摘した罠に自分で落ちた。** 止めたのは vault の報告と、自分の木での再現。
47. 🆕 **部分文字列一致は、両方向に転ぶ。** `grep -c -- '--limit 100'` は **`--limit 1000` に一致する**
    （自艦で再現: 境界なし=1／境界つき=0／実値=1000）。今回は「直っていないように見える」方向だったので
    気づけたが、**逆方向なら緑のまま素通りしていた**。
    🔑 **境界つき grep より「実値を抜いて数値比較」が上位**（`grep -oE -- '--limit [0-9]+'`）——
    **境界つき grep は正しく書けたときだけ正しい。**
48. 🆕 **同じ検査を複数 workflow へ配るなら、Issue タイトルを workflow ごとに分ける。**
    同一タイトルだと dedup が働いて **frontend の赤を backend のスレッドへ追記**し、
    **どちらが落ちたか分からなくなる**。🔑 **dedup が正しく働くほど悪化する罠。**
    単一 workflow の艦（serve）から写すときに必ず踏む。
49. 🆕 **承認は中継できない。** 08-22 に hub 経由の「施主承認」を2回とも使わなかった。
    1回目は**保留した窓の中で #287 の inert な穴が出た**（伝聞のまま押していたら穴ごと main に入っていた）。
    2回目に **hub の像が「wave3 未許可／#287 承認済み」＝実態と逆**だと判明した。
    判定に使ったのは一つだけ——**その言葉を自分が直接受け取ったか**。
    🔑 **縫い目は「守ると安全」ではなく「守った回数だけ事故が止まる」。**
50. 🆕 **探索パスは、自艦の名前でも決め打ちしない。** 起動時の指示書チェックを
    `handoff-*fleet*tooling*` で引き、**`handoff-fleet-2026-08-21-...` を見落とした**。
    ⇒ **`handoff-*fleet*` まで広げる。** 名前の一部が一致しない命名は普通に存在する。

🔴 **lockfile を触るときの手順**（判例44・正本 = `_work/reports/2026-07-21-full-close-playbook.md` §7）:
0. **着手前に、その艦の CI が lockfile 以外に何を同時に要求するかを測る** ＝ **⑦**
1. 変更前後で **`packages` の件数**を比較 ／ 2. **版が動いた全パッケージ**と**昇格/降格の向き**を見る
3. **workspaces / 複数 lockfile の有無**を先に確認する ／ 4. PR 本文に 0〜3 の**全数**を書く
5. **`npm audit fix` ではなく `npm update <対象>` を狙い撃ちする** ＝ **⑧**
